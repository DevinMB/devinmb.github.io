# Projects

<p class="intro">A run of things I've built for the fun of it — small services wired together with Kafka, a bit of hardware and radio, and a homelab to run it all on. The throughline: turning noisy real-world signals into something useful, with no cloud bill.</p>

<section class="project">
  <div class="project-header">
    <h2>The Chair&trade;</h2>
    <span class="project-tag">Load cells &times; Kafka</span>
  </div>
  <p class="project-lead">
    Curiosity about load cells turned into a fully event-driven sensor platform. A load
    cell under my living-room chair streams weight data into Kafka, where a pipeline of
    small services turns raw readings into meaningful <em>sit</em> events — driving
    everything from automated lighting to a live analytics dashboard. Built to scale:
    more sensors to come.
  </p>

<section class="project">
  <div class="project-header">
    <h2>Whisper Bot</h2>
    <span class="project-tag">ML pipelines on Kafka</span>
  </div>
  <p class="project-lead">
    My friends share an anonymous meme chat with a constant firehose of messages — a
    perfect playground for Kafka and machine learning. Whisper Bot consumes the chat,
    trains a model on it, and once a day posts a (gloriously absurd) message of its own.
    The results are silly; the pipeline behind them is the fun part — now evolving toward
    LLAMA 2 with embeddings.
  </p>

<section class="project">
  <div class="project-header">
    <h2>Farm Sensor Network</h2>
    <span class="project-tag">LoRa IoT</span>
  </div>
  <p class="project-lead">
    A long-range, solar-powered sensor network for monitoring conditions out in the field,
    where Wi-Fi doesn't reach. Battery-friendly ESP32 nodes speak raw point-to-point LoRa —
    deliberately skipping LoRaWAN and Meshtastic overhead — to a Raspberry Pi hub that feeds
    a Go API and a live dashboard. Designed for nodes that run for years on a small panel,
    and the dashboard can even flash new firmware to a board straight from the browser.
  </p>

  <div class="components">
    <div class="component">
      <div class="component-top">
        <span class="component-title">Field Sensors</span>
        <a class="component-repo" href="https://github.com/DevinMB/farm-iot/tree/main/firmware/esp32">Repo</a>
      </div>
      <p class="component-desc">ESP32 (Heltec V3) firmware sending a compact binary payload over SX1262 LoRa, with solar and deep-sleep power budgeting — and nRF52 boards under evaluation for even lower sleep current.</p>
    </div>
    <div class="component">
      <div class="component-top">
        <span class="component-title">LoRa Hub</span>
        <a class="component-repo" href="https://github.com/DevinMB/farm-iot/tree/main/backend/hub">Repo</a>
      </div>
      <p class="component-desc">A Go daemon on a Raspberry Pi that receives LoRa packets off the radio and relays them upstream.</p>
    </div>
    <div class="component">
      <div class="component-top">
        <span class="component-title">API &amp; Consumer</span>
        <a class="component-repo" href="https://github.com/DevinMB/farm-iot/tree/main/backend/api">Repo</a>
      </div>
      <p class="component-desc">Go services handling auth, farms, hubs, and nodes, with secrets managed in HashiCorp Vault.</p>
    </div>
    <div class="component">
      <div class="component-top">
        <span class="component-title">Dashboard</span>
        <a class="component-repo" href="https://github.com/DevinMB/farm-iot/tree/main/frontend">Repo</a>
      </div>
      <p class="component-desc">A React/TypeScript dashboard with live sensor charts — and in-browser ESP32 flashing for new nodes.</p>
    </div>
  </div>
</section>

<section class="project">
  <div class="project-header">
    <h2>Personal Health Pipeline</h2>
    <span class="project-tag">Self-hosted data engineering</span>
  </div>
  <p class="project-lead">
    A self-hosted pipeline that turns phone and wearable sensor data into a personal health
    dashboard — end to end, with no cloud dependency. The same Kafka instincts from my day
    job, pointed at my own data.
  </p>

  <div class="components">
    <div class="component">
      <div class="component-top"><span class="component-title">Sources</span></div>
      <p class="component-desc">Home Assistant exposes phone and wearable sensors and streams every reading into the pipeline.</p>
    </div>
    <div class="component">
      <div class="component-top"><span class="component-title">Stream</span></div>
      <p class="component-desc">A single Kafka topic carries it all, with consumer-side filtering that keeps the producers dumb and simple.</p>
    </div>
    <div class="component">
      <div class="component-top"><span class="component-title">Store</span></div>
      <p class="component-desc">CouchDB persists each reading under an idempotent <code>{entity_id}:{last_updated}</code> document id, so replays never double-count.</p>
    </div>
    <div class="component">
      <div class="component-top"><span class="component-title">Dashboard</span></div>
      <p class="component-desc">A mobile-first React + Vite + Recharts frontend for vitals, activity, and sleep trends — built to extend to new data sources.</p>
    </div>
  </div>
</section>
